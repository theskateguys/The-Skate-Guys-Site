### Final timeout: 25 seconds

Use `requestTimeoutMs: 25000`, including the fallback in lead-capture.js. Nine seconds is below the measured real browser response (9244.5ms) and the measured Sheets phase alone (12117ms; total instrumented doPost 12394ms). The earlier full save took 17983ms. A 25-second client deadline provides about seven seconds beyond that observed full execution for redirects/network/startup variation, without promising a latency SLA. Twenty seconds would leave only about two seconds beyond the earlier slow execution. No deadline guarantees storage or successful acknowledgement under every outage/cold start.

The timeout applies ONLY to the background website-delivery attempt. The prepared WhatsApp link is exposed before fetch and remains usable throughout. At timeout, keep the entered details, say "The browser timed out; storage may still complete," and allow a manual same-ID retry. Do not call an opaque/failed/late response saved. A matching readable acknowledgement is still mandatory. Retain disabled reminders and duplicate protection.

`automation/check-booking-timeout.js` reads the actual 25000ms configuration, changes only the endpoint to an intercepted synthetic destination, and uses real wall-clock application timers.
